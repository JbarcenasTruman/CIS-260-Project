# CIS-260-Project: Cybersecurity Documentation
A Project for the City Colleges of Chicago CIS 260 Class.

# Project Information
With the rise of malicious actors in the tech world, vigilance is key to monitoring incoming and outgoing network traffic. 
In this project, I will be demonstrating how to monitor a network within a closed environment. I will use Cisco Packet Tracer to display the network flow between 3 computers. Two will connect via Ethernet to a modem, while one will connect via Wi-Fi. After seeing how data flows in Packet Tracer, I will rebuild the environment inside a VM using Oracle VM. Utilizing Wireshark (or any other tools needed) on the VM, I will spot and capture any malicious packets. Then, to ensure they can't be leaked out or brought in to cause havoc again, I will write a cybersecurity report to prevent this from affecting an office or business environment, and implement fixes and next steps to prevent the next attack. This project helps us understand how an IT office works and what issues may arise. It also helps to understand how to write these reports so the documentation can be used and saved for future reference, or if a similar attack happens again.

# Setup and Scenario
First, we build a network overlay topology inside Cisco Packet Tracer. With a visual, we can show how a small office can have multiple different device setups and how they use the network for everyday tasks. The end devices will be 2 Pc nodes and one laptop node with Wi-Fi capabilities. The network itself will have one switch, one access point, and one router. The Laptop with Wi-Fi capabilities will be the bad actor in this scenario. Using Oracle VirtualBox, it will run two PC VMs with different Linux versions. Using a network branch inside VirtualBox, I can show how a malicious actor breaches the network and connects to a PC inside the office. By running a program or terminal command that mimics a packet being sent, I can send something to the office network, into one of the PCs, and cause havoc. Then, as someone investigating what is going on, like an IT tech or Network administrator, I will use Wireshark to record what type of packet it is and then write a report to prevent the issue from happening again and implement a fix.


# Cyber Security Report
A Template for a Cybersecurity report will be used for this project. Network environments are always different and set up in specific ways so that any report will vary depending on the IT office and environment. This template is the basis for what most reports will look like and will be filled out accordingly. It notes what the packet is, what it interrupted, and how it got into the network. It also identifies vulnerabilities in the network, how to fix the issue, and the next steps to prevent it from happening again. The document is extensive and serves as a basis for what every IT security office documents. The Template provided on GitHub is an example of what most offices use; it may not always be the same, but we will use it for this project. The purpose of this is to understand better how cybersecurity works and how network protection is possible. A draft is listed within and will be filled out as the project goes along.

# Goals of this project
The goal of this project is to learn how packets work in a network environment. It also covers how attacks can affect an office space and how to prevent attacks from happening again. The report is also a learning experience about how IT offices, security admins, and system technicians work around the clock to protect the network from network failures and hackers. This is also a way to practice writing reports and thinking like a technician. This experience can be used for future projects or a part-time office job. The report template can be edited as needed for each network or security environment. It will also teach me how to use packet sniffing programs like Wireshark.
